# Переписывание Memiro по agent-coding-instruction

**Status:** ready-for-agent

Спека собрана из реестра решений `.scratch/rewrite/decisions.md` (гриллинг
завершён 2026-08-25, решения 1–61; сверка с закрывшимися тикетами MVP
2026-08-26 добавила решения 62–64). Реестр — документ
записи: при расхождении формулировок правда там. Канон стека и процесса —
`.scratch/rewrite/agent-coding-instruction.md` (копия в этом каталоге); референсный
репозиторий — `lubaskinc0de/dreamteams`. Доменная правда — `CONTEXT.md` и
ADR-0002…0011 этого репозитория.

## Problem Statement

Сайт ещё не запущен, а его код уже одноразовый. Нынешний репозиторий — MVP на
Django-монолите: домен размазан по моделям, вьюхам и сигналам, расчёт цены —
главная ценность сайта — переплетён с ORM, границы агрегатов нигде не
проведены, а правила живут пятью предикатами там, где хватило бы одного.
Владелец хочет, чтобы расчёт был образцово чистым, строго по DDD и чистой
архитектуре, плотно покрыт тестами — и чтобы дальше сайт писали агенты по
единой инструкции, а не по фольклору конкретного кодека. Нынешний код под эту
инструкцию не подгоняется — он ей противоречит устройством.

При этом наработанное терять нельзя: домен разобран до тонких правил
(CONTEXT.md, ADR-0002…0011), и Django-админка — рабочее место владельца,
которое он уже знает.

## Solution

Сайт переписывается с нуля по agent-coding-instruction: FastAPI + async
SQLAlchemy 2.0 (imperative mapping) + alembic + dishka, витрина — Astro SSR с
островами Vue, формат репозитория — в точности §2 инструкции. Из старого
репозитория переезжают только доменные документы: CONTEXT.md (разобранный на
страницы сущностей и VO) и ADR-0002…0011; старый код остаётся справочником по
домену и не мигрируется.

Django сохраняется ровно в одной роли — админка владельца: вторая презентация
того же bounded context. Читает она напрямую по зеркалам доменных таблиц
(`managed = False`), пишет — через те же интеракторы, что и API; доменные
глаголы — действиями админки, не CRUD.

Расчёт цены становится ядром: один чистый доменный сервис, всё параметрами,
в базу не ходит; результат — VO `Quotation` с enum-вердиктом вместо россыпи
булевых. Наценка за размер (ADR-0010) реализуется сразу внутри расчёта. Книга
xlsx — интерактор над тем же сервисом, второй реализации расчёта в репозитории
нет.

Процесс — строго §17→§18: walking skeleton, затем вертикальные срезы по
use case, каждый — doc-first страница, красный интеграционный тест, домен,
приложение, адаптеры, DI, презентация, одним PR ≤500–700 строк. Первый срез —
`calculate_price`.

## User Stories

1. Как владелец, я хочу, чтобы расчёт цены на новом сайте давал те же числа,
   что книга xlsx на рабочем столе, потому что книга — канон, и админка
   обязана повторять её один-в-один.
2. Как владелец, я хочу сохранить Django-админку, чтобы не переучиваться на
   новое рабочее место ради переписывания, которого я не вижу.
3. Как владелец, я хочу заводить категории, атрибуты и тарифы без
   разработчика, как обещает ADR-0002, — переписывание этого не отменяет.
4. Как владелец, я хочу, чтобы правка тарифа или параметров расчёта
   пересчитывала цены вариантов и «цену от» товаров, чтобы витрина не
   показывала вчерашние числа.

   нового сайта, чтобы крупные зеркала не продавались по цене средних ни дня.

## Implementation Decisions

Полный реестр — `.scratch/rewrite/decisions.md` (61 решение); здесь — каркас.
Номера в скобках — решения реестра.

**Стек и топология.** Стек инструкции дословно: FastAPI, async SQLAlchemy 2.0
imperative mapping, alembic, dishka, structlog + OTel; формат репозитория — §2
(1). Один bounded context `memiro`; `memiro_common` — примитивы §5 плюс
observability (3). За nginx четыре сервиса: frontend (Astro SSR, Node), api
(uvicorn, async), admin (gunicorn, WSGI, sync), migrations one-shot; api и
admin — один образ, разные команды (4). Витрина — Astro SSR, интерактив —
острова Vue; калькулятор и форма заявки — острова; Pinia не заводим (5, 38).
Кэша и Redis в контуре нет; триггер пересмотра — метрики после запуска (51).

**Схема и данные.** Alembic — единственный владелец доменных таблиц;
Django-миграции владеют только служебными; в alembic — фильтр чужих таблиц
(8). Доменные Django-модели — зеркала `managed = False` с явным `db_table`
(9); дрейф ловит тест сверки метаданных SQLAlchemy против моделей Django:
таблицы, колонки, nullable, грубый тип, уникальные констрейнты; дефолты не
сверяются; во всех зеркалах `on_delete=DO_NOTHING` (10, 58). Идентификаторы —
UUID через PEP 695 `type`-алиасы; в публичных URL — slug (11).

**Домен.** Критерий границы агрегата: правило, обязанное выполняться всегда,
держит участников вместе; терпящее рассинхрон — врозь, связь событием (21).
Корни: `Product` (с `DeclaredValue`, `Variant`), `Attribute` (с
`AttributeValue`), `PricingSettings` (со ступенями наценки), `Inquiry` (с
`InquiryItem`), `Category`, `Landing` (с `LandingCondition`) (22). Контент без
правил доменных сущностей не получает: DTO + read-гейтвей; сущность заводится
при первом инварианте (49). Между агрегатами — только id (24). Одна
транзакция — один агрегат; кросс-агрегатное — событие после коммита, несёт
только идентификаторы (25). Сигналы Django исчезают; пересчёт цен — хендлер
событий со своей транзакцией, пачками, без оптимизаций — потолок каталога
100–300 товаров по 3–10 вариантов зафиксирован владельцем (26, 50). «Цена от»
— производное поле, пересчитываемое поштучными командами над вариантами
(добавить, поправить, удалить, размножить с другим размером — ADR-0011);
дубликаты вариантов по размеру+значениям запрещены внутри агрегата; порядок
вариантов — поле владельца, на первом подходящем открывается калькулятор
покупателя (23, 62). Позиция заявки хранит слепок и не
пересчитывается (27).

**Расчёт цены.** Один доменный сервис: товар, справочник, параметры, размеры
и выбор — параметрами, результат — VO `Quotation` (total, breakdown,
verdict); verdict — enum `PRICED | BEYOND_LIMITS | NOT_PRICEABLE | HIDDEN`
(28, 31). Второй реализации нет: книга xlsx — интерактор над тем же сервисом,
openpyxl — адаптер, запуск — команда собственного CLI (29). Protocol движка
убирается: замена формулы — изменение домена (30). Наценка за размер — сразу,
внутри расчёта, перемножается с формой, множит только помеченные значения
(32). Русские тексты из домена уходят; наружу — машинный код (33). Величины —
VO (`Millimeters`, `Dimensions`, `Money`, `Rate`, `Area`, `Perimeter`);
поворот изделия и «ноль = нет предела» — внутри них (34). «Дорос до расчёта»
— одно межагрегатное правило в сервисе вместо пяти предикатов MVP (35).
Тонкие правила CONTEXT.md — дробный `Decimal`, `marks_absence`, молчание на
пустоте — переезжают (36). Публично — единственный эндпоинт расчёта с
усечённой проекцией: итог, дельты добавок, verdict-код, строка-объяснение;
полный breakdown — только внутрь; гейт погашенной цены действует и на
эндпоинт (55). У расчёта два спрашивающих (ADR-0011): покупательский вопрос
проходит все гейты — публикация, считаемый набор, меняемость атрибута, предел
производства, погашенная цена — и получает вердикт; владельческий вопрос
конструктора вариантов гейтов не проходит — вариант заводит тот, кто знает,
что производство возьмёт. Сервис, тарифы и число общие; гейты — принадлежность
покупательского вопроса, не ядра (63).

**Слои и админка.** Админка — вторая презентация контекста, пакет рядом с
FastAPI-презентацией, не отдельный контекст (40). Чтение — по зеркалам:
changelist, фильтры, поиск, история (12). Запись всего, у чего есть
инварианты, — через интеракторы; прямой CRUD — только контент без правил
(13–15). Inline-формсеты: сохранение собирает корень и детей в одну команду и
зовёт один корневой интерактор — одна транзакция, полная замена детей;
бизнес-отказ — сообщение об ошибке и возврат на форму, ничего не сохранено.
Схема действует для атрибута со значениями, параметров расчёта со ступенями и
посадочной с условиями; варианты товара из неё выходят: их правит конструктор
в карточке (ADR-0011) — поштучные команды агрегата с живой ценой до
сохранения, инлайна вариантов нет (60, 62). Порядок моста: сначала интерактор (коммит домена), затем Django-часть
(история, баннеры) best-effort (47). Мост async — постоянный фоновый поток с
одним event loop на процесс админки, контейнер и engine живут в нём честным
APP-scope (59). Доменные глаголы — действиями админки (16). Оператор — не
доменная сущность; права — Django permissions; интеракторы анонимны (17).
Синглтоны MVP исчезают: параметры расчёта и контакты — сущности с известным
id, в админке редирект на единственный объект (19). Фото — порт хранилища
(локальный диск на томе, S3 позже заменой адаптера); в зеркале — строковый
ключ (18, 54). Контракты import-linter: админку не импортирует никто; django
не встречается вне её презентации и bootstrap; домен и приложение не знают
фреймворков (41). Ошибки — §5.3/§12 дословно: плоская иерархия, SCREAMING
код, таблица соответствия HTTP в двух глобальных хендлерах (42).

**Фронт и SEO.** Sitemap, robots, meta/OG, canonical, JSON-LD, редиректы
легаси — на фронте; бэк отдаёт данные (37). Авторизации на фронте нет (38).
У фронта свой AGENTS.md; правила инструкции на TypeScript не распространяются
(39). SEO переживает будущую смену стека при сохранении URL; триггер
пересмотра — личный кабинет (48). i18n нет, русский захардкожен (55).

**Уведомления.** Заявка — всегда в БД; нотификация best-effort. Канал один —
почта: Telegram удалён из MVP по слову владельца «только почта» (тикет 19),
переносить нечего; составной нотификатор и порт остаются точкой расширения,
MAX — потом (53, 57, 64). Уроки MVP-адаптера переносятся: таймаут SMTP,
шифрование из порта, пустой адрес менеджера — предупреждение в лог, заявка не
страдает. Провайдер известен — Яндекс.Почта, ящик отправителя тоже; needs-info
на этапе деплоя — адрес менеджера и пароль приложения.

**Процесс.** Строго §17 (bootstrap) → §18: doc-first → красный интеграционный
тест → домен → приложение → адаптеры → DI → презентация, вертикальными PR
≤500–700 строк (43). Порядок срезов: `calculate_price` (walking skeleton +
самая плотная часть домена) → `submit_inquiry` → `browse_catalog` → админка
(зеркала + тест дрейфа, потом ModelAdmin'ы) → контент/SEO (44). До первого
кода — AGENTS.md, разбор CONTEXT.md на страницы сущностей и VO по §16.2,
переезд ADR-0002…0011 как есть, ADR-0001 помечается заменённым, плюс новые
ADR (мост админки: порядок записи и loop-поток; Astro с триггером пересмотра;
граница пересчёта каталога) — всё это оформляется отдельной задачей очереди,
не ад-хок (45, 61).

## Testing Decisions

Хороший тест проверяет поведение снаружи — цену, ответ эндпоинта, состояние
базы после команды, — а не устройство внутри. Канон — §14 инструкции целиком:
десять правил, testcontainers + template database, типизированный ApiClient,
фабрики polyfactory, Hypothesis в unit по стратегиям (46). Локальный контур —
Postgres в docker; SQLite уходит (52).

Швы — три, зафиксированы гриллингом:

1. **Unit на домен** — плотнее всего на пакете расчёта цены: чистый сервис
   без базы позволяет табличные случаи и Hypothesis тысячами прогонов.
   Закрывается арифметика: единицы расхода, два множителя (форма × наценка),
   пороги и округления, вердикты, поворот изделия, «ноль = нет предела»,
   молчание на пустоте.
2. **Интеграционные через ApiClient** — по одному пакету на use case, 1:1 со
   слоем приложения; самый высокий шов, через него тестируется и то, что
   зовёт админка (интеракторы общие). Плотнее всего — на расчёте цены; сюда
   же тест-забор приватности: в публичном JSON нет ставок, коэффициентов и
   статей (55).
3. **Тест дрейфа зеркал** — сверка метаданных SQLAlchemy против моделей
   Django; единственный тест, знающий обе схемы (10, 58).

Прежнее искусство — тесты MVP (`test_pricing`, `test_price_endpoint`,
`test_price_from_variants`): их случаи — готовый список поведения для
переноса, сам код тестов не мигрируется.

## Out of Scope

- **Миграция старого кода и данных.** Пишем с нуля; старый репозиторий —
  справочник по домену. Скрипт переноса контента — отдельная работа, когда
  до неё дойдёт очередь.
- **Второй bounded context.** Один `memiro`; душевые перегородки живут в нём
  категорией.
- **Кэш и Redis.** Нет в контуре вовсе; пересмотр — по метрикам после
  запуска, первым шагом nginx proxy_cache.
- **S3.** Порт готов, адаптер локальный; замена — конфигурацией DI позже.
- **Мессенджер MAX как канал нотификаций.** Порт готов, канал — когда
  понадобится.
- **i18n.** Русский захардкожен.
- **Личный кабинет.** Его появление — триггер пересмотра фронтовой
  архитектуры (отдельное SPA), не сегодняшняя работа.
- **Оптимизация пересчёта цен.** Пачками без хитростей; граница
  применимости (100–300 товаров) — в ADR о пересчёте.
- **Реквизиты почты для прода** (адрес менеджера, пароль приложения
  Яндекс.Почты). Needs-info у владельца на этапе деплоя; код от ответа не
  зависит.
