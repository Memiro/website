# 16: Bootstrap админки — зеркала и тест дрейфа

**What to build:** Владелец входит в знакомую Django-админку под штатными правами и читает доменные данные: changelist'ы, фильтры, поиск, история. Django — вторая презентация того же контекста (решение 40): пакет рядом с FastAPI-презентацией; доменные модели — зеркала `managed = False` с явным `db_table`, `on_delete=DO_NOTHING`; alembic — единственный владелец доменных таблиц, Django-миграции владеют только служебными, в alembic — фильтр чужих таблиц. Сервис admin (gunicorn, WSGI) — тот же образ, что api, другая команда; one-shot миграций расширяется: alembic, затем django migrate; collectstatic на сборке, nginx отдаёт статику админки. Тест дрейфа зеркал (решения 10/58): сверка метаданных SQLAlchemy против моделей Django — таблицы, колонки, nullable, грубый тип, уникальные констрейнты; дефолты не сверяются. Контракты import-linter: админку не импортирует никто, django не встречается вне её презентации и bootstrap.
