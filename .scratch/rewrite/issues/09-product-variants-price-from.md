# 09: Варианты товара и «цена от»

**What to build:** Агрегат Product умеет вести предпосчитанные варианты поштучными командами (ADR-0011, решения 23/62): добавить, поправить, удалить, размножить с другим размером; каждая команда пересчитывает производное поле «цена от» последней строкой; дубликаты по размеру+значениям запрещены внутри агрегата; порядок вариантов — поле владельца. Цена варианта считается владельческим вопросом (без гейтов) тем же сервисом. Поведение проверяется через интеракторы `manage_products` интеграционными тестами — админский конструктор позже станет тонкой презентацией над этими командами. Случаи старого `test_price_from_variants` — список поведения для переноса.

## Comments

- `Product` владеет приватными вариантами и производной `_price_from`: четыре
  команды пересчитывают минимум последней строкой, наружу доступны только
  read-only свойства. Порядок стабилен по `sort_order`, затем по id.
- Дубликат определяется повёрнутым размером и итоговой конфигурацией. No-op
  overrides канонизируются относительно деклараций товара, порядок overrides
  не влияет на fingerprint; домен и unique constraint защищают одно правило.
- Все четыре `manage_products`-интерактора блокируют строку товара, eager-load'ят
  детей, считают цену владельческим вызовом единственного pricing service и
  делают один commit. Временного HTTP-роута нет: тесты используют согласованный
  production Dishka REQUEST scope с настоящим Postgres.
- Миграция добавляет nullable `products.price_from` и `product_variants` с
  каскадом, check и unique constraint. JSONB проходит доменные конструкторы;
  повреждённые overrides или fingerprint не гидратируются молча.
- Двухосевое ревью исправило внешнее присваивание цены/ребёнка, семантический
  дубль через значение товара, живой порядок, проверку гидрации, структуру
  тестов/docs и отдельный import-linter contract.
- Проверки: `just lint`, `just static`, `just test` — 350 passed.
