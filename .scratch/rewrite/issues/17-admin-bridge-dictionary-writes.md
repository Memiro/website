# 17: Мост админки и запись справочников

**What to build:** Владелец заводит атрибуты со значениями и правит параметры расчёта со ступенями без разработчика (ADR-0002, user story 3) — через те же интеракторы, что и API. Мост async (решение 59, ADR из тикета 02): постоянный фоновый поток с одним event loop на процесс админки, dishka-контейнер и engine живут в нём честным APP-scope. Inline-формсеты (решение 60): сохранение собирает корень и детей в одну команду и зовёт один корневой интерактор — одна транзакция, полная замена детей; бизнес-отказ — сообщение об ошибке и возврат на форму, ничего не сохранено наполовину (user story 7). Порядок моста: сначала интерактор (коммит домена), затем Django-часть (история, баннеры) best-effort (решение 47). Синглтон-паттерн MVP исчезает: PricingSettings — сущность с известным id, редирект с changelist на единственный объект. Единица расхода — enum домена, в админке не редактируется.

**Blocked by:** 16 (bootstrap админки)

**Status:** ready-for-agent

- [ ] Атрибут со значениями сохраняется одной транзакцией через корневой интерактор
- [ ] Параметры расчёта со ступенями наценки правятся формой с редиректом на единственный объект
- [ ] Бизнес-отказ интерактора возвращает форму с сообщением; в БД ничего не изменилось (тест)
- [ ] Падение Django-части после коммита — warning, домен не откатывается
- [ ] История правок (LogEntry) пишется — владелец видит кто и что менял (user story 6)
