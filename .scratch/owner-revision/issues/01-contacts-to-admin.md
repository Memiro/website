# 01 — Контакты студии переезжают в админку

**What to build:** Контакты студии — адрес, телефон, почта, ссылки, часы, карта —
становятся данными админки вместо констант в коде. Первым делом на новых данных
меняется адрес шоурума.

**Why:** Сегодня всё это лежит словарём `CONTACTS` в `src/memiro/context_processors.py`.
Смена адреса требует разработчика и выкатки — а владелец меняет адрес чаще, чем
выходит релиз. Это тот же принцип, по которому в админке живут атрибуты (ADR-0002)
и пороги расчёта (ADR-0007): данные владельца — не код.

**Blocked by:** None.

**Status:** ready-for-human

- [x] Модель контактов — одна строка на сайт, по образцу `PricingSettings`
      (`SINGLETON_PK`, `save()` прибивает pk)
- [x] Поля: город, улица, телефон, телефон для показа, e-mail, часы работы,
      `opens`/`closes` для разметки, ссылки на мессенджеры и VK, ссылка на Avito,
      код встраиваемой карты
- [x] Город и улица — раздельными полями: разметке `LocalBusiness` они нужны
      порознь, витрине одной строкой (сохранить свойство `address`)
- [x] Пустая ссылка означает «не показывать», а не битую иконку — правило уже
      действует для `opens`/`closes` в `seo/structured.py`
- [x] Контекст-процессор `contacts` отдаёт ту же структуру ключей, что и сейчас:
      шаблоны не переписываются
- [x] `seo/structured.py` берёт контакты оттуда же, а не из константы
- [x] Миграция данных переносит нынешние значения `CONTACTS` в первую строку —
      сайт после миграции выглядит как до неё
- [x] Адрес меняется на «Александра Матросова, 4к2ж» (пункт 3 списка владельца)
- [x] Словарь `CONTACTS` из `context_processors.py` удалён
- [x] Тесты: страница «Контакты» и футер печатают значение из админки;
      пустая ссылка не даёт иконки

**Не делать:** реквизиты продавца (`legal/seller.py`) не трогать — это другая
сущность, у неё свои требования и свой `manage.py check`.

## Comments

2026-08-24 (agent, реализация): контакты живут строкой `content.SiteContacts`,
данные из словаря перенесены миграцией `content/0005_contacts_from_code.py`,
адрес заменён на «Александра Матросова, 4к2ж».

Что вышло за буквальный список:

- **Обязательные и необязательные поля разошлись.** Телефон, показываемый
  телефон, почта, город, улица и часы — обязательные: витрины без них
  не бывает, и охранять каждый `tel:` в семи шаблонах значило бы верстать
  сайт без телефона. Правило «пустое — не показывать» осталось там, где
  поле и правда необязательно: мессенджеры, ВКонтакте, Avito, карта.
- **Часы для разметки стали временем, а не строкой:** «25:99» до поисковика
  не доедет, а одна заданная граница расписания отвергается `clean()` —
  без пары разметка о часах молчит, и заполненное в одиночку поле молча
  пропало бы.
- **Разметка не называет незаполненный контакт:** пустой `telephone` или
  профиль пустой строкой — то же враньё поисковику, что выдуманное
  расписание. `LocalBusiness` печатает только заполненное.
- **Строка одна на сайт — теперь одно правило на два раздела.** Появился
  `memiro/singleton.py` (`SingletonModel` + `SingletonAdmin`); на него
  переведены и контакты, и параметры расчёта — до этого пороги несли свою
  копию `save()` и разрешений админки. Миграций перевод не потребовал.
- **Строка читается один раз за запрос** (`context_processors.site_contacts`):
  её спрашивают и шаблон, и разметка. Побочное следствие переезда — витрина
  теперь ходит в базу на каждой странице, включая статические; в тестах,
  которые рендерили страницы без базы, добавлена фикстура `db`.

Осталось владельцу: заполнить точные часы (`opens`/`closes`) — до тех пор
разметка о расписании молчит; проверить адрес и карту на «Контактах».
