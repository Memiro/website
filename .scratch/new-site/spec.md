## Problem Statement

Действующий сайт студии (memiro.ru) — WordPress с темой, экспортированной из Webflow. Владельцу сложно и дорого его развивать: тарифы калькулятора цен зашиты в 599 строк JavaScript внутри темы (вместе с себестоимостью и коэффициентами наценки, открытыми любому посетителю), контент управляется связкой платных плагинов, сайт отвечает десятками секунд. Владелец хочет сайт, который быстро работает, отлично индексируется, красиво выглядит и позволяет управлять каталогом через админку без разработчика — включая появление новых типов товаров (душевые перегородки и далее).

Терминология и доменная модель — в `CONTEXT.md`; ключевые решения — в `docs/adr/` (0001 SSR-монолит, 0002 атрибуты-справочники, 0003 посадочные). Юр. требования — `docs/research/ru-legal-requirements-2025-2026.md`.

## Solution

Новый сайт с нуля: Django-монолит с SSR-шаблонами, нативной админкой и JSON-эндпоинтами на django-modern-rest для интерактива (калькулятор, заявка, «показать ещё»). Дизайн — handoff-пакет редизайна, утверждённый владельцем как внешний вид (тикет 12, ADR-0004); «Свет» (тикет 02) остался в истории. Модель данных проектируется от домена, старые сущности WordPress ничего не диктуют; перенос 88 товаров — одноразовым скриптом после сборки бека. Продакшен — VPS Beget (РФ, что также требование 152-ФЗ), старый сайт живёт до переключения DNS; статьям старого блога — 410, товарам и страницам — 301.

## User Stories

1. As a посетитель, I want открывать страницы практически мгновенно, so that я не ухожу из-за ожидания
2. As a посетитель, I want просматривать каталог с фото и ценами «от X ₽», so that я могу выбрать изделие (цена есть у каждого товара — режима «цена по запросу» нет)
3. As a посетитель, I want фильтровать каталог по характеристикам (мгновенно на десктопе, через drawer на мобиле, со счётчиками значений и блоком применённых фильтров), so that я быстро сужаю выбор
4. As a посетитель, I want открыть карточку товара с галереей, характеристиками и ценой, so that я вижу всё о товаре в одном месте
5. As a посетитель, I want рассчитать цену под мой размер прямо в карточке, so that я понимаю стоимость до обращения
6. As a посетитель, I want добавлять товары в избранное и корзину-подборку, so that я отправлю менеджеру заявку на несколько позиций сразу
7. As a посетитель, I want оставить заявку (имя, телефон, email, комментарий) без регистрации и оплаты, so that студия со мной связалась
8. As a посетитель, I want написать в WhatsApp/Telegram в один клик, so that я задаю вопрос привычным способом
9. As a посетитель, I want посмотреть «Наши работы», отзывы и FAQ, so that я снимаю сомнения перед заявкой
10. As a посетитель, I want видеть акции и страницы «О нас», «Доставка и возврат», «Контакты» (карта, часы шоурума), so that я понимаю условия и доверяю студии
11. As a посетитель, I want комфортно пользоваться сайтом с телефона, so that мне не нужен компьютер
12. As a владелец, I want заводить категории, их атрибуты и товары в админке, so that новый тип товара (перегородки) появляется без разработчика
13. As a владелец, I want отмечать товары флагом «популярное» с порядком, so that блок на главной наполняется вручную
14. As a владелец, I want редактировать тарифы и коэффициенты калькулятора в админке, so that изменение цен не требует программиста — и не светит мою маржу в клиентском коде
15. As a владелец, I want управлять акциями, отзывами, FAQ и «Нашими работами» из админки, so that маркетинговый контент всегда актуален
16. As a владелец, I want заводить SEO-посадочные на фильтры (ЧПУ, title/h1, текст) в админке, so that сайт ловит среднечастотные запросы
17. As a владелец, I want видеть все заявки в журнале админки и получать уведомление в Telegram, so that ни одна не теряется
18. As a владелец, I want чтобы сайт удовлетворял 152-ФЗ, ПП 2463 и практике РКН, so that проверка или жалоба не обернётся штрафом
19. As a владелец, I want чтобы сайт выбивал ~100 баллов в PageSpeed и SEO-валидаторах, so that качество подтверждено измеримо
20. As a разработчик (агент), I want подменяемый движок расчёта цены, so that будущая переработка калькулятора дешева
21. As a разработчик (агент), I want править тексты статических страниц в коде, so that правка текста — минутный коммит

## Implementation Decisions

- **Архитектура**: Django-монолит, SSR-шаблоны, без SPA и Node (ADR-0001). JSON — django-modern-rest (калькулятор, заявка, «показать ещё»).
- **Модель каталога**: категории плоские; общие поля товара (название, слаг, цена «от», описание, артикул, фото малое+большое, галерея, флаги популярное/акция, порядок) — колонки; фильтруемые характеристики — справочник атрибутов с привязкой к категории, простые типы: выбор из списка, да/нет, число (ADR-0002). Категория видна на витрине только с опубликованными товарами. Наличия в модели нет — всё под заказ («отказные» готовые зеркала — будущая отдельная задача).
- **Каталог/фильтры**: QuerySet-фильтрация, ИЛИ внутри атрибута / И между; мгновенное применение на десктопе (левый сайдбар), drawer с кнопкой «Показать N» на мобиле; счётчики значений, блок применённых фильтров, «Сбросить всё»; сортировка: цена ↑↓, популярность, новинки. Пагинация: «Показать ещё» поверх настоящих `?page=n` с `<a>`-ссылками и self-canonical.
- **SEO**: фасетные URL закрыты (robots + canonical на категорию + Clean-param); индексируемые посадочные — ручной белый список в админке: ЧПУ, свой title/h1/текст (ADR-0003). Черновики текстов и подбор спроса (Wordstat) — агент, утверждение — владелец. JSON-LD: Product+Offer на карточке, BreadcrumbList везде, LocalBusiness (шоурум СПб: адрес, часы). Sitemap из БД, 301-карта со старых `/mirrors/<slug>` (генерируется скриптом переноса), статьям — 410.
- **Заявки**: корзина и избранное — localStorage; заявка — POST на эндпоинт → запись в БД + Telegram (транспорт подменяем). Терминология — «заявка», не «заказ» (см. CONTEXT.md); на кнопках витрины текст свободный.
- **Калькулятор**: серверный расчёт, ставки и коэффициенты — только в БД/админке, в клиент уходит одна итоговая цена. Модель расчёта (тарифы, комбинации, опции) проектируется отдельной сессией — тикет 06 её ждёт.
- **Юр. соответствие** (тикет 10): политика ПД + отдельные непредотмеченные чекбоксы у каждой формы; уведомление РКН до запуска форм (владелец); cookie-баннер, не грузящий Яндекс.Метрику до согласия; реквизиты (ОГРН/ОГРНИП) в футере и контактах; оговорка о невозврате изделий по индивидуальным размерам (ст. 26.1 ЗоЗПП) на «Доставке и возврате»; дисклеймер «не публичная оферта» у цен; шрифты (Manrope) — самохостинг, никаких Google Fonts/иностранных виджетов.
- **Аналитика**: только Яндекс.Метрика, за cookie-согласием.
- **БД**: SQLite в разработке, PostgreSQL в продакшене. **Хостинг**: VPS Beget (РФ — требование локализации ПД).
- **Дизайн**: действующий визуальный язык — handoff-пакет редизайна (`design/mockups-v2/`, тикет 12, ADR-0004); «Свет» (тикет 02) выведен из работы. Макет задаёт вид, но не структуру: при расхождении побеждают юр. требования, затем SEO-политика и доменная модель.
- **Перенос данных**: одноразовый скрипт вне кодовой базы, запускается после готовности новой модели; маппинг старых ACF-полей — забота скрипта, не модели.

## Testing Decisions

- Хороший тест проверяет только внешнее поведение, видимое пользователю или клиенту API.
- **Основной шов — HTTP**: каталог содержит товары из БД; фильтр отсекает лишнее; посадочная отдаёт свой title/h1/текст; POST заявки создаёт запись и триггерит уведомление (Telegram подменён); страницы отдают корректные метатеги и JSON-LD; закрытые фасетные URL несут canonical/robots-сигналы; Метрика отсутствует в HTML до согласия.
- **Второй шов — движок цены**: чистая функция, табличные тесты (параметры + тарифы → цена).
- Других швов нет. Вёрстка проверяется владельцем по макетам; стандартная админка отдельно не тестируется.

## Out of Scope

- Модель калькулятора (отдельная сессия проектирования; тикет 06 ждёт её)
- Статус наличия / продажа готовых «отказных» зеркал (будущая задача)
- Финальный SEO-прогон на ~100 баллов (перед запуском)
- Заказ и настройка VPS, деплой, переключение DNS
- Блог/новости, личные кабинеты, онлайн-оплата, автогенерация фасетных страниц, Algolia/Elastic
