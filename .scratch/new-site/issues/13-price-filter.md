# 13 — Фильтр по цене в каталоге

**What to build:** Сужение выдачи каталога по цене — единственное сужение, которое строится не из атрибутов категории, а из самого поля товара. В макете редизайна это ползунок с верхней границей (`design/mockups-v2/Memiro - Каталог.dc.html`, блок под группами фильтров).

**Blocked by:** 12 — Редизайн витрины: новый визуальный язык

**Status:** ready-for-human

## Что решить до реализации

- **Форма контроля.** ✅ Решено 2026-08-20: два поля «от» и «до» вместо ползунка из макета. Ползунок из макета задаёт только верхнюю границу и не даёт ввести число руками. Альтернатива — два поля «от» и «до»: точнее, доступнее с клавиатуры и переживает категории с разным разбросом цен. Решение за владельцем, вид подгоняется под токены пакета.
- **Границы диапазона.** В макете зашиты 3 000–40 000 ₽. У каждой категории разброс свой, а после переноса 88 товаров (тикет 11) он изменится — границы должны считаться из данных категории, а не жить в вёрстке.
- **SEO.** Цена добавляет в URL ещё один фасетный параметр. По ADR-0003 он закрывается от индексации наравне с остальными: robots, canonical на категорию, Clean-param для Яндекса. Проверить, что новый параметр действительно попал в закрывающие правила тикета 09.
- **Взаимодействие со счётчиками.** Счётчики значений атрибутов считаются с исключением своей группы; ограничение по цене должно учитываться во всех счётчиках, включая свою группу — цена группой не является.
- **Пустой результат.** Комбинация «фильтры + цена», не находящая ничего, должна вести себя как остальные пустые комбинации (сейчас — 404, тикет 04).

## Acceptance criteria

- [x] Границы диапазона считаются из опубликованных товаров категории, в вёрстке не зашиты — *`PriceControl.build`: `Min`/`Max` по цене категории уходят в `placeholder`; при единственной цене контрол не выводится*
- [x] Диапазон цены комбинируется с фильтрами атрибутов (И между ними) и попадает в чипы применённых фильтров с крестиком — *два чипса, «от» и «до» снимаются по отдельности*
- [x] Счётчики значений атрибутов учитывают выбранный диапазон цен — *`PriceRange.apply` вызывается до исключения группы, `exclude` цены не касается*
- [x] Параметр цены закрыт от индексации наравне с прочими (ADR-0003) — *`PRICE_PARAMS` идут в `Disallow` и `Clean-param`, canonical на категорию даёт `is_active`*
- [x] Контрол доступен с клавиатуры, у него есть подпись, значение читается скринридером — *два `input[type=number]` с `aria-label` «Цена от, ₽» / «Цена до, ₽»*
- [x] HTTP-тесты: диапазон сужает выдачу; пустая комбинация ведёт себя как остальные пустые — *`tests/test_catalog_pages.py`, блок «Диапазон цены»*

## Comments

2026-08-20 (agent, реализация): владелец выбрал два поля вместо ползунка — ползунок задаёт только верхнюю границу и не переживает категории с разным разбросом. Параметры названы `price_min`/`price_max`, а не по-русски: они не растут из атрибутов, и слаг атрибута с ними не столкнётся. Мусорное значение цены — `FilterError` → 404, как мусорный токен атрибута; проверка строже `int()` (`isascii` и `isdigit`), иначе `1_000` и `+900` давали бы 200 и чип, которого посетитель не набирал. В глоссарий добавлен «Диапазон цены»: «Фильтр» там определён через атрибуты, а цена растёт из поля товара.

2026-08-20 (agent, двухосевое ревью): границы категории сначала стояли в `min`/`max` полей, а `catalog.js` перед переходом звал `checkValidity()`. Это запирало форму: приходишь по старой ссылке с ценой вне нынешних границ (товар подорожал, крайний снят с публикации) — и клик по любому чекбоксу атрибута упирается в подсказку браузера вместо перехода. Теперь границы — только `placeholder`, ограничение одно и на сервере, гейт из JS убран. Подпись цены больше не форматируется в `filters.py`: там был свой пробел-разделитель, а в `catalog_tags.rub` — узкий неразрывный, и на одной странице получались два разных числа одного вида; чип зовёт `rub`.

**Осталось на потом:** перепутанные границы (`price_min` больше `price_max`) отдают 404 по общей ветке пустой комбинации — местами менять их молча нельзя, крестик чипа снимает границу по совпадению значения с querystring. Если владелец увидит на этом отказы, ответом будет объяснение на странице пустой выдачи (тикет 04), а не тихая перестановка.

2026-08-21 (agent, второй раунд двухосевого ревью): поля цены выпали из мгновенного применения фильтров — у `input[type=number]` событие `change` случается на blur, и Tab из «от» в «до» перезагружал страницу на полузаполненном диапазоне; теперь блок применяется на `focusout`, когда фокус ушёл из него целиком, и не трогает страницу, если URL не изменился. `min="0"` из полей убран: после решения «границы — только подсказка» он срабатывал на Enter и молчал на остальных путях, то есть работал через раз. Разбор границы стал строже одного каноничного числа: `08352` и второй такой же параметр давали чип, крестик которого снимает не ту границу (или не снимает вовсе), — теперь это 404, как прочий мусор. Форматирование цены переехало из `templatetags` в обычный модуль `catalog/formatting.py`: домен не должен зависеть от шаблонного слоя, а шаблонный фильтр `rub` стал обёрткой. `AppliedFilter.slug` переименован в `param` — у цены это не слаг атрибута. Поля цены не наследовали `height`/`flex` от `.fgroup input` (чекбокс 15×15) и выходили обрезанными — правило дополнено.

**Открытый вопрос владельцу:** у фильтров-атрибутов в пустую комбинацию ткнуть нельзя (нулевые значения `disabled`, на мобиле кнопка гаснет), а у цены — можно: набрал «от 12 000» в категории, где дороже нет, и получил 404 без сайдбара, назад только кнопкой браузера. Аккуратный ответ — не 404, а пустое состояние «Под эти условия ничего нет» с кнопкой сброса (оно есть в макете каталога), но это меняет правило тикета 04 для всех фильтров сразу, поэтому решать владельцу.
