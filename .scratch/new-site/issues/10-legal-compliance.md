# 10 — Юридическое соответствие (152-ФЗ, ПП 2463, практика РКН)

**What to build:** Сайт проходит юр. проверку по чек-листу `docs/research/ru-legal-requirements-2025-2026.md`: страница «Политика обработки ПД»; отдельные непредотмеченные чекбоксы согласия у каждой формы со ссылкой на политику и фиксацией факта согласия в БД; cookie-баннер, который НЕ грузит Яндекс.Метрику до нажатия «Согласен» (пассивный баннер не защищает по практике РКН 2025); реквизиты продавца (наименование/ФИО ИП, ОГРН/ОГРНИП, адрес, контакты) в футере и на «Контактах»; дисклеймер «цены не являются публичной офертой» у каталога и калькулятора; шрифты — самохостинг (никаких Google Fonts/иностранных CDN/виджетов — локализация ПД по 23-ФЗ).

**Blocked by:** 05 — Главная, статические страницы и «Наши работы», 07 — Избранное, корзина и заявка

**Status:** ready-for-human

- [x] Страница «Политика обработки ПД», ссылки на неё из каждой формы и футера
- [x] Чекбоксы согласия (непредотмеченные) у всех форм; факт согласия сохраняется с заявкой
- [x] Cookie-баннер: Метрика подключается только после явного согласия; выбор запоминается
- [ ] Реквизиты продавца в футере и на «Контактах» — механика готова, но значений нет, и на витрине реквизитов пока не видно
- [x] Дисклеймер «не публичная оферта» у цен каталога — категория, посадочная, карточка (у результата калькулятора — вместе с тикетом 06)
- [x] Шрифты самохостятся; в HTML нет запросов к иностранным сервисам
- [x] HTTP-тесты: без согласия Метрики нет в отдаче; формы без чекбокса отклоняются; политика отвечает 200
- [ ] **Владелец**: подать уведомление РКН об обработке ПД (pd.rkn.gov.ru) ДО запуска форм — бесплатно; штраф за неподачу 100–300 тыс. ₽
- [ ] **Владелец**: вписать реквизиты продавца в `src/memiro/legal/seller.py` (ФИО ИП/наименование, ОГРН(ИП), ИНН, адрес места нахождения) — без них сайт не соответствует п. 18 ПП 2463
- [ ] **Владелец**: вычитать текст политики и согласия (`templates/pages/privacy.html`); при правке текста поднять `PRIVACY_VERSION` в `legal/consent.py`
- [ ] **Владелец**: завести счётчик Яндекс.Метрики и положить его номер в `YANDEX_METRIKA_ID` — до этого cookie-баннер не показывается, потому что спрашивать не о чем

## Comments

2026-08-19 (agent, грилинг): последний пункт — ready-for-human: сделать может только владелец. Текст политики ПД драфтит агент по шаблонам из ресёрча, владелец вычитывает.

2026-08-20 (agent, реализация): механика собрана целиком, дальше нужны данные владельца.

- Согласие на аналитику решает сервер, а не JS: выбор в cookie `cookie_consent`, до «Принять» ни счётчика, ни его номера в HTML нет. Обоснование и цена решения (перезагрузка при согласии) — ADR-0006.
- Реквизитов и номера счётчика у владельца пока нет (спрошено 2026-08-20). Реквизиты живут одной таблицей `legal/seller.py`; пустое поле не печатается — выдуманный ОГРН хуже отсутствующего. До заполнения пункт ПП 2463 формально не закрыт.
- К факту согласия добавлена редакция текста (`Inquiry.consent_version`, миграция 0002): «лог согласий» из чек-листа ресёрча без версии текста ничего не доказывает.
- Дисклеймер «не оферта» лежит одним партиалом `legal/_offer_note.html` и включён в категорию, посадочную и карточку. Калькулятора нет (тикет 06) — когда он появится, партиал надо будет поставить и под результат расчёта.
- Скриншотами вёрстку не проверял: в этом окружении нет браузера. Cookie-баннер, блок реквизитов и страницу политики стоит глянуть глазами.

2026-08-20 (agent, двухосевое ревью): правки по обоим отчётам.

- `PRIVACY_VERSION` уехала из `legal/consent.py` в `legal/privacy.py`: согласие на ПД и cookie-согласие на аналитику — разные вещи, и модуль не должен меняться по двум причинам сразу.
- Реквизиты стали `@dataclass(frozen=True) Seller` вместо словаря с параллельным списком подписей — по образцу `seo/meta.PageMeta`; тест подменяет их `monkeypatch.setattr`, а не мутацией глобала.
- Дубль ссылки на политику в футере убран (осталась нижняя строка), `cookies.js` уехал в сам партиал баннера — условие `cookie_choice.needed` теперь одно.
- Cookie согласия пишется с `Secure` под https; `_counter()` переименована в `_metrika_id()`; протухший комментарий на «Контактах» переписан на ADR-0006.
- Про `Vary: Cookie` дописан абзац в ADR-0006: заголовок уже стоит (session/CSRF middleware), но зависимость теперь явная — появится кеш, проверять первым делом.
- Галочка по реквизитам снята: механика есть, требования п. 18 ПП 2463 без значений не выполнено.
- Тест на самохостинг шрифтов оставлен единственным читающим файл: HTTP-шов не достаёт содержимое `site.css`, а `@import` на Google Fonts внутри стилей утёк бы мимо остальных проверок. Причина записана в самом тесте.
