# 22 — Справочник по набору владельца и переразметка товаров

**What to build:** Справочник приводится к набору, который описал владелец: тип полотна, форма, рама, подсветка, температура свечения, кнопка, крепление, подогрев, вырез. Разметка 88 перенесённых товаров переезжает на новый набор — однозначное переносит скрипт, остальное владелец проставляет в админке. До этого калькулятор на боевых данных не включится, потому что система не знает, контурная у зеркала лента или фронтальная.

**Blocked by:** 15 — Тариф в справочнике атрибутов

**Status:** ready-for-agent

## Набор атрибутов

| Атрибут | Значения | Меняет покупатель |
|---|---|---|
| Тип полотна | серебро · осветлённое · бронза · графит | да |
| Форма | прямоугольное · круглое · фигурное | нет |
| Рама | алюминий · багет · (пусто — без рамы) | нет |
| Подсветка | контурная · фронтальная · комбинированная · (пусто) | нет |
| Температура свечения | холодная · тёплая · нейтральная · 3 в 1 | нет |
| Кнопка | механическая · сенсорная · датчик на взмах · (пусто) | нет |
| Крепление | с креплением · на ножке · (пусто) | да |
| Подогрев | с подогревом · (пусто) | да |
| Вырез | количество · (пусто) | нет |

Тип полотна обязателен. Кнопка зависит от подсветки и подогрева и одна на изделие: второй выключатель — личное пожелание. Пустое значение означает отсутствие признака, а не «не указано». Цвет рамы остаётся как есть — он ничего не стоит и нужен только фильтру.

## Что переносится, а что нет

- **Скриптом:** «Материал рамы: Алюминий» → «Рама: алюминий»; «Расположение: Напольное» → «Крепление: на ножке»; «Форма» и «Цвет рамы» остаются как есть.
- **Владельцем:** вид подсветки, температура, тип полотна, кнопка, подогрев, вырез. Старое «С подсветкой» не говорит, контурная лента или фронтальная, а от этого зависит, считать по периметру или по площади. Угадывать нельзя — получится молча неверная цена.

- [ ] Справочник приведён к набору выше
- [ ] Переносимая разметка перенесена скриптом; повторный прогон ничего не портит
- [ ] Скрипт живёт в `.scratch/`, в продакшен-код и зависимости проекта не попадает
- [ ] Незаполненное видно в админке: товар без типа полотна или без вида подсветки калькулятор не включает
- [ ] По типу полотна фильтр не строится и посадочные на него не заводятся
- [ ] Новая категория со своими атрибутами и тарифами заводится без разработчика — обещание ADR-0002 живо
- [ ] Тесты: переразметка на копии данных даёт ожидаемый набор; товар с незаполненным обязательным атрибутом расчёт не включает

## Notes

**Владельцу:** после прогона скрипта проставить вид подсветки, температуру, тип полотна, кнопку, подогрев и вырез там, где они есть. Все 88 товаров — черновики и всё равно ждут вычитки, так что это тот же проход. Пока не сделано, товар цены не показывает — он ждёт своего первого предпосчитанного варианта.
