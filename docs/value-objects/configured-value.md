# ConfiguredValue

## Назначение

Значение одного настроенного атрибута в единственной форме: строка справочника
для `SELECT` или дробное количество для `NUMBER`. Эту пару не дублируют
`DeclaredValue`, выбор покупателя и расчёт — все передают один VO.

В коде — `entities/catalog/product/entity.py`.

## Состав

| Поле | Тип | Смысл |
|---|---|---|
| `value_id` | `AttributeValueId \| None` | Выбранная строка справочника для `SELECT` |
| `quantity` | `Decimal \| None` | Количество для `NUMBER` |

## Business Rules

1. `value_id` и `quantity` не бывают заданы одновременно. Такое состояние —
   дефект вызывающего кода: `RuntimeError`, а не бизнес-отказ.
2. Оба поля могут быть пустыми только у незавершённой декларации владельца:
   для применимого атрибута пустота значит «ещё не дошёл», и покупательский
   расчёт отвечает `NOT_PRICEABLE`; отключённый выбором родителя дочерний
   атрибут в расчёте не участвует. Публичный ввод требует ровно одно поле и
   иначе получает `VALIDATION_ERROR` (422).
3. Количество хранится как дробный `Decimal`; два с половиной погонных метра
   не округляются до целого.
4. Количество не бывает отрицательным — иначе `INVALID_QUANTITY` (400). Ноль
   законен: это объявление «столько и не нужно», а не пропуск. Отрицательный
   расход доехал бы до `Rate.charge` и вышел бы из `Money` как 500, тогда как
   покупателю причитается отказ.
5. Своего идентификатора у VO нет. В таблице деклараций SQLAlchemy собирает его
   через `composite()` из колонок `value_id` и `quantity`.

## Где используется

`DeclaredValue` внутри [`Product`](../entities/product.md), выбор покупателя в
use case [`calculate_price`](../usecase/calculate_price/calculate-price.md) и
доменный сервис `pricing_service`.
