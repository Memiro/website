# Attribute — атрибут

## Назначение

Характеристика товара, заведённая в админке и привязанная к категории:
«подсветка», «форма», «тип полотна». Из атрибутов автоматически строятся фильтры
каталога — из тех, у которых стоит признак «строит фильтр». Владелец заводит
новую категорию с её атрибутами без разработчика (ADR-0002).

Атрибут же образует цену: у значения есть единица, в которой оно расходуется, и
тариф. Отдельной сущности «опция» в домене нет — подсветка и рама описывают
товар и стоят денег одновременно, и заводить их дважды владелец не должен
(ADR-0007).

_Avoid_: свойство, характеристика, опция, настройка.

Корень агрегата; внутри — значения `AttributeValue`. В коде —
`entities/catalog/attribute/`.

## Атрибуты

| Поле | Тип | Смысл |
|---|---|---|

| `is_filterable` | `bool` | Строит фильтр каталога |
| `sort_order` | `int` | Порядок, поле владельца |
| `values` | `list[AttributeValue]` | Значения справочника, дети агрегата |
| `created_at` | `datetime` | |
| `updated_at` | `datetime` | |

### AttributeValue — значение справочника

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `AttributeValueId` | Идентификатор (UUID) |
| `name` | `str` | Название: «серебро», «без рамы», «вырез» |
| `rate` | [`Rate`](../value-objects/rate.md) | Ставка и единица расхода |
| `scaled_by_shape` | `bool` | Дорожает на криволинейном резе |
| `scaled_by_size_surcharge` | `bool` | Дорожает на крупном изделии |
| `marks_absence` | `bool` | Значит «этого у изделия нет» |
| `sort_order` | `int` | Порядок, поле владельца |

## Business Rules

1. Виды атрибута — `SELECT` (выбор из списка) и `NUMBER` (число). Вида «да/нет»
   в домене нет: «нет рамы» — это значение справочника с `marks_absence`, и
   второй правды об отсутствии домен не заводит (решение 66; ADR-0002 писался,
   когда вид ещё был).
2. Числовой атрибут говорит не «что выбрано», а «сколько раз»: два выреза стоят
   вдвое. Тариф у него живёт там же, где у всех, — единственной строкой его
   справочника, ставкой за единицу. У атрибута вида `NUMBER` значение ровно
   одно; больше — `NumericAttributeNeedsSingleValueError`.
3. Количество для числового атрибута — дробный `Decimal`: два с половиной
   погонных метра остаются двумя с половиной.
4. Отсутствие признака называется своим значением справочника — «без рамы»,
   «без подсветки», — а не пустотой. Пустая строка значит «владелец ещё не
   дошёл», и на ней расчёт молчит. `marks_presence()` — обратная сторона того же
   признака, одно правило на проверку ввода в админке и на гейт калькулятора.
5. Зависящий атрибут (`parent_id`) применим к товару только тогда, когда у
   товара выбрано значение родителя с `marks_presence`: кнопка существует, только
   когда есть подсветка. На отсутствие зависящий атрибут не опирается — иначе
   товару без подсветки расчёт не включился бы никогда.
6. Родитель — атрибут той же категории, и цепочка не замыкается в кольцо:
   нарушение — `AttributeCycleError`.
7. `scaled_by_shape` и `scaled_by_size_surcharge` — два разных признака, потому
   что множества разные: коэффициент формы берёт полотно и раму, наценка за
   размер — одно полотно. Рама на трёхметровом зеркале сложнее своего метража не
   становится, а лента этот метраж уже оплатила периметром (ADR-0010). Одной
   единицей расхода эти случаи не различить: контурная лента меряется тем же
   погонным метром, что и обработка кромки, но на криволинейном резе дороже не
   становится.
8. `is_filterable` — одно определение на фильтр каталога и на право завести
   посадочную: по нефильтруемому атрибуту посадочной не бывает, иначе
   индексируемая страница сужала бы каталог сужением, которого в сайдбаре нет.
   Не всякий атрибут фильтрует: любое зеркало делают из любого полотна, и группа
   «серебро / графит» прятала бы подходящие товары.
9. `is_customer_changeable` — не тот же признак: подогрев и крепление покупатель
   меняет, и сузить по ним каталог тоже осмысленно. Неменяемый атрибут всё равно
   участвует в расчёте: лента и профиль считаются по периметру, а периметр
   зависит от размеров, которые вводит покупатель.
10. Значение платное, когда его ставка ненулевая. Бесплатное значение остаётся
    описанием товара и в цену не входит.
11. Набор значений меняется целиком одной командой корня (`replace_values`):
    админка собирает корень и его инлайн-формсет в один `UpdateAttributeData` и
    вызывает один интерактор — одна доменная транзакция (решение 60).
12. Все платные строки справочника владелец видит и правит ещё и плоским
    списком — экраном админки «Материалы и цены». Второй правды о цене экран не
    заводит: это тот же справочник, показанный поперёк атрибутов. «Материал» —
    слово владельца, а не сущность домена.

## Жизненный цикл и связи

```
Category
  └── Attribute            (по category_id)
        ├── parent ──► Attribute   (по parent_id, та же категория)
        └── AttributeValue*        (дети агрегата, replace_values)
                └── Rate           (ставка + единица расхода)
```

Изменение тарифа — событие `TariffChanged`, опубликованное строго после коммита;
его хендлер пересчитывает цены товаров пачками (решения 25, 26; ADR-0014).
