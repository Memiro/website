# Category — категория

## Назначение

Плоский раздел каталога: зеркала, душевые перегородки. Категория — тип товара,
а не витринный блок. Иерархии нет: «подкатегории» выражаются атрибутами и
посадочными.

_Avoid_: раздел, рубрика, подкатегория.

Корень агрегата без детей. В коде — `entities/catalog/category.py`.

## Атрибуты

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `CategoryId` | Идентификатор (UUID) |
| `name` | `str` | Название на витрине |
| `slug` | `str` | Адрес в публичном URL |
| `sort_order` | `int` | Порядок в каталоге, поле владельца |
| `created_at` | `datetime` | |
| `updated_at` | `datetime` | |

## Business Rules

1. Родителя у категории нет и не будет. Сужение внутри типа товара — дело
   фильтров и посадочных: «зеркала с подсветкой» это [`Landing`](landing.md),
   а не вторая категория.
2. `slug` уникален по сайту: на нём стоят адреса каталога и посадочных.
   Нарушение — `CategorySlugTakenError`; уникальность видна транзакции, а не
   агрегату, и ошибка живёт в `application/errors/` (§12.2).
3. Смена `slug` — смена публичного адреса, и старый попадает в карту переезда
   (`LegacyUrl`), а не исчезает молча.
4. Видимость на витрине не хранится полем: категория видна, когда содержит хотя
   бы один опубликованный товар. Считает это read-путь каталога, потому что
   правило терпит рассинхрон — публикация товара живёт в своём агрегате
   (решение 21).
5. Атрибуты привязаны к категории. Товар заполняет применимые к нему атрибуты
   своей категории, и «все применимые заполнены» — условие того, что товар
   вообще считается (см. [`Product`](product.md)).

## Связи

```
Category
  ├── Attribute*   (по category_id, ссылка идентификатором)
  ├── Product*     (по category_id)
  └── Landing*     (по category_id)
```

Между агрегатами — только идентификаторы, никогда объект (решение 24).
