# Правка корня атрибута

**Актор:** владелец, установленный Django-презентацией.

Карточка админки шлёт эту команду второй, после `replace_values`; если она
откажет, справочник уже сохранён, и админка говорит об этом баннером
(тикет 09).

Владелец правит сам атрибут — название, вид, зависимость от других атрибутов,
признак «меняет покупатель», порядок. Значения справочника эта команда не
трогает: их заменяет [`replace_values`](replace-values.md).

## Input

`ChangeAttributeForm` — те же поля корня, что и у
[заведения](create-attribute.md) (`name`, `kind`, `parent_ids`,
`is_customer_changeable`, `is_filterable`, `sort_order`), кроме `category_id`
и `values`: раздел атрибута не переезжает.

## Output

`None`.

## Business Rules

1. Границы формы — те же, что при заведении, иначе `VALIDATION_ERROR` (422).
2. Атрибут существует — иначе `ATTRIBUTE_NOT_FOUND` (404).
3. Каждый родитель — атрибут той же категории, не сам атрибут, и круга в
   родстве не образуется — иначе `INVALID_ATTRIBUTE_PARENT` (400).
4. Смена вида на числовой законна только при одной строке справочника —
   иначе `INVALID_ATTRIBUTE_VALUE_SET` (400): вид и набор значений держат
   один инвариант, и владелец сначала приводит набор к одной строке.
5. Корень меняется, `updated_at` двигается последней строкой часами
   параметром, одна транзакция одного агрегата коммитится. Ошибки нет.

## Errors

| Код | HTTP | Когда |
|---|---|---|
| `VALIDATION_ERROR` | 422 | Форма не прошла границы ввода |
| `ATTRIBUTE_NOT_FOUND` | 404 | Атрибута нет |
| `INVALID_ATTRIBUTE_PARENT` | 400 | Родитель не той категории, это сам атрибут или родство замкнулось в круг |
| `INVALID_ATTRIBUTE_VALUE_SET` | 400 | Числовому атрибуту нужна ровно одна строка справочника |
