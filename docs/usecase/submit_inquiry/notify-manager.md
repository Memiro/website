# Уведомить менеджера о заявке

## Назначение

После сохранения заявки менеджер получает письмо с неизменяемым снимком её
позиций. Доставка не меняет результат отправки заявки посетителю.

## Актор

Система после анонимного посетителя, отправившего заявку.

## Вход

| Поле | Тип | Смысл |
|---|---|---|
| `inquiry_id` | `InquiryId` | Идентификатор уже сохранённой заявки |

## Выход

Нет. Уведомление — best-effort действие после коммита заявки.

## Правила

1. Уведомление начинается только после коммита агрегата `Inquiry` (кода ошибки
   нет: действие best-effort).
2. Канал загружает сохранённый снимок заявки по её идентификатору. Письмо
   содержит каждую позицию отдельным ТЗ: название, габариты, выбранные
   значения, личное пожелание, цену и вердикт. Оно не загружает живые тарифы
   или справочник (кода ошибки нет: действие best-effort).
3. Ошибка отдельного канала не отменяет сохранённую заявку и не меняет
   успешный ответ посетителю (кода ошибки нет: действие best-effort).
4. Если адрес менеджера не задан, SMTP-канал пропускается и пишет warning без
   персональных данных. Составной нотификатор принимает включённые каналы
   списком (кода ошибки нет: действие best-effort).
5. SMTP использует таймаут из конфигурации, а шифрование выводит из её порта:
   `465` — SSL, `587` — STARTTLS. Канал почты можно выключить конфигурацией
   (кода ошибки нет: действие best-effort).

## Ошибки

Бизнес-ошибок нет: недоступность почтового канала является ожидаемой
деградацией и не попадает в HTTP-контракт.
