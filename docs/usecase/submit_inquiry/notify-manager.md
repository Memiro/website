# Уведомить менеджера о заявке

## Назначение

После сохранения заявки менеджер получает письмо с неизменяемым снимком её
позиций. Доставка не меняет результат отправки заявки посетителю.

## Актор

Система после анонимного посетителя, отправившего заявку.

## Вход

| Поле | Тип | Смысл |
|---|---|---|
| `inquiry_id` | `InquiryId` | Идентификатор уже сохранённой заявки |

## Выход

Нет. Уведомление — best-effort действие после коммита заявки.

## Правила

1. Уведомление начинается только после коммита агрегата `Inquiry` (кода ошибки
   нет: действие best-effort).
2. Канал загружает сохранённый снимок заявки по её идентификатору. Письмо
   содержит каждую позицию отдельным ТЗ: название, габариты, спецификацию
   строками «Атрибут: значение» в порядке снимка, цену одной строкой и личное
   пожелание. Оно не загружает живые тарифы или справочник (кода ошибки нет:
   действие best-effort).
3. Вердикт менеджеру называется словами, кода вердикта в письме нет
   (`Inquiry`, правило 19). Строка цены по вердикту: `PRICED` — «Цена:
   12 000 ₽»; `HIDDEN` — «Цена: 12 000 ₽ (покупателю не показана)»;
   `BEYOND_LIMITS` — «Цена не рассчитана: размер за пределом производства»;
   `SELECTION_NOT_PRICEABLE` — «Цена не рассчитана: расчёт не взял этот
   выбор»; `NOT_PRICEABLE` — «Товар без расчёта», без размера и спецификации.
   Карточка заявки в админке читает позицию теми же словами.
4. Итога у письма нет: ни суммы позиций, ни «от» (`Inquiry`, правило 18).
5. Ошибка доставки не отменяет сохранённую заявку и не меняет успешный
   ответ посетителю: канал гасит её у себя (кода ошибки нет: действие
   best-effort).
6. Если адрес менеджера не задан или у учётной записи SMTP нет пароля, письмо
   не отправляется: канал пишет warning без персональных данных и выходит до
   чтения заявки и без похода в сеть (кода ошибки нет: действие best-effort).
   Так один конфиг служит всем контурам: без файла пароля канал молчит.
7. SMTP использует таймаут из конфигурации, а шифрование выводит из её порта:
   `465` — SSL, `587` — STARTTLS. Пароль в конфиге не лежит: секция `[email]`
   называет файл `password_file` (относительный путь — от каталога конфига),
   загрузчик читает из него одну строку; файла нет — пароль пуст. Канал почты
   можно выключить конфигурацией — выключенный не отправляет ничего; порт
   уведомления реализует он один (кода ошибки нет: действие best-effort).

## Ошибки

Бизнес-ошибок нет: недоступность почтового канала является ожидаемой
деградацией и не попадает в HTTP-контракт.
