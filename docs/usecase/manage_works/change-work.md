# Правка работы

**Актор:** владелец, установленный Django-презентацией.

Владелец правит подпись, описание, ссылку на товар, порядок и публикацию
работы, а при желании заменяет и саму фотографию. Интерактор зовёт карточка
работы в админке через мост.

## Input

`work_id: UUID` и `ChangeWorkForm`

| Поле | Тип | Смысл |
|---|---|---|
| `photo` | `PhotoForm \| None` | Новая фотография; пустое поле оставляет прежнюю |
| `product_id` | `UUID \| None` | Зеркало с фотографии, пока каталог его продаёт |
| `title` | `str` | Подпись под фотографией |
| `description` | `str` | Абзац о том, что и где ставили |
| `is_published` | `bool` | Черновик витрине не показывается |
| `sort_order` | `int` | Место в галерее |

## Output

Ничего.

## Business Rules

Правила идут в порядке, в котором их проверяет интерактор.

1. Границы ввода — те же, что при заведении, иначе `VALIDATION_ERROR` (422).
2. Работа существует — иначе `WORK_NOT_FOUND` (404).
3. Названный товар существует — иначе `PRODUCT_NOT_FOUND` (404).
4. Новая фотография пишется на том до строки; правка без фотографии не
   трогает том вовсе.
5. Ключ, который хранилище выдало второй раз, — `RuntimeError` (500):
   см. «Заведение работы», правило 4.
6. Отказ базы забирает новый файл обратно, а прежняя фотография остаётся той,
   которую называет строка.
7. Прежний файл удаляется только после коммита: до него строка ещё называет
   его, и витрина читает именно строку.

## Errors

| Код | HTTP | Когда |
|---|---|---|
| `VALIDATION_ERROR` | 422 | Форма не прошла границы ввода |
| `WORK_NOT_FOUND` | 404 | Работы с названным идентификатором нет |
| `PRODUCT_NOT_FOUND` | 404 | Товара с названным идентификатором нет |
| `INTERNAL_ERROR` | 500 | Хранилище выдало ключ живой строки |
