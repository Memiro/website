# Товары категории

**Актор:** анонимный посетитель витрины.

Посетитель получает опубликованные товары выбранной категории по публичному
slug, сузив и упорядочив выдачу фильтрами сайдбара. Чтение не меняет каталог
и не пересчитывает цену.

## Input

| Поле | Тип | Смысл |
|---|---|---|
| `category_slug` | `str` | Публичный slug категории из списка категорий |
| `values` | `list[UUID]` | Выбранные значения атрибутов, до 50 штук (`?value=` в адресе) |
| `price_min`, `price_max` | `Decimal \| None` | Границы цены «от» товара, обе необязательны |
| `sort` | `CatalogSort` | `name` (по умолчанию), `cheapest`, `dearest` |
| `page` | `int` | Номер страницы, с единицы |

## Output

`ProductsList` — конверт `{items, total, page, pages, groups, price, sort}`.

| Поле | Тип | Смысл |
|---|---|---|
| `items` | `list[ProductSummary]` | Страница товаров: `name`, `slug`, `price_from`, `image_keys`, `updated_at` |
| `total` | `int` | Сколько товаров подходит под сужение всего |
| `page` | `int` | Запрошенная страница |
| `pages` | `int` | Сколько страниц по 24 товара получилось; у пустой выдачи — одна |
| `groups` | `list[FilterGroup]` | Группы фильтров: атрибут, его строки, счётчики и отметки |
| `price` | `PriceBounds` | Границы цены категории и то, что выбрал посетитель |
| `sort` | `CatalogSort` | Порядок, в котором выдача действительно собрана |

## Business Rules

1. Страница содержит только опубликованные товары своей категории. Ошибки нет.
2. Значения одного атрибута объединяются по ИЛИ, разные атрибуты — по И
   (CONTEXT.md, ADR-0002). Ошибки нет.
3. Группы фильтров дают атрибуты вида `select`, у которых стоит признак
   «строит фильтр»: числовой атрибут вводится числом и группы не даёт, а
   снятый признак убирает атрибут из сайдбара — по типу полотна выдачу не
   сужают, любое зеркало делают из любого полотна. Признак отдельный от
   «меняет покупатель»: крепление и подогрев покупатель тоже меняет, а сузить
   по ним каталог осмысленно. Группы и строки идут в `sort_order` владельца.
   Ошибки нет.
4. Счётчик строки — сколько товаров она оставит при всех остальных выбранных
   фильтрах и цене, но без учёта выбора в своей же группе (практика Baymard):
   иначе после первого клика счётчики соседних строк обнулились бы. Ошибки нет.
5. Цена сужает по полю товара `price_from`, а не по атрибутам, и потому
   учитывается в счётчиках всех групп. Товар без `price_from` выпадает, как
   только названа любая граница: цены, которая попала бы в диапазон, у него
   нет. Ошибки нет.
6. Значение, не принадлежащее ни одному фильтруемому атрибуту этой категории,
   отбрасывается: старая ссылка остаётся страницей категории, а не пустой
   выдачей и не отказом. Ошибки нет.
7. Порядок: по названию (по умолчанию), по цене вверх и по цене вниз. Товар
   без цены в обоих ценовых порядках идёт последним — он не самый дешёвый,
   он тот, о цене которого сайт молчит. Ошибки нет.
8. Страница за последней — пустая выдача с настоящим `total`, а не отказ:
   так ведёт себя устаревшая ссылка на страницу, которой больше нет.
   Ошибки нет.
9. `price_from` — сохранённая цена самого дешёвого предпосчитанного варианта;
   у товара без вариантов её нет, и витрина цену не показывает (ADR-0007).
   Ошибки нет.
10. Публичный JSON не раскрывает ставку, единицу расхода, коэффициент или
    строки внутреннего расчёта. Ошибки нет.

## Errors

| Код | HTTP | Когда |
|---|---|---|
| `CATEGORY_NOT_FOUND` | 404 | Slug не принадлежит ни одной категории |

Пустая категория — пустой конверт, а не отказ.
