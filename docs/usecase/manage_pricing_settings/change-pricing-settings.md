# Правка параметров расчёта

**Актор:** владелец, установленный Django-презентацией.

Владелец двигает границы, в которых живёт расчёт: снизу — минимальную площадь
и минимальную сумму заказа, сверху — предел производства по наибольшей и второй
стороне; и заменяет набор ступеней наценки за размер. Всё это один агрегат
(`pricing-settings.md`), поэтому экран уходит **одной командой корня**: отказ на
ступени оставляет границы там, где владелец их застал.

Строка параметров на сайте одна и заведена вместе с сайтом: команда её правит,
но не создаёт и не удаляет — в админке changelist редиректит на единственный
объект.

## Input

`ChangePricingSettingsForm`

| Поле | Тип | Смысл |
|---|---|---|
| `min_area` | `Decimal` | Минимальная площадь расчёта, м² |
| `min_order_total` | `Decimal` | Минимальная сумма заказа, ₽ |
| `max_long_side_mm` | `int` | Предел по наибольшей стороне; ноль значит «предела нет» |
| `max_short_side_mm` | `int` | Предел по второй стороне; ноль значит «предела нет» |
| `surcharges` | `list[SizeSurchargeRowForm]` | Набор ступеней целиком — какой должен остаться |

`SizeSurchargeRowForm`

| Поле | Тип | Смысл |
|---|---|---|
| `from_long_side_mm` | `int` | Наибольшая сторона, с которой ступень действует |
| `factor` | `Decimal` | Коэффициент ступени |

Идентификатора у ступени нет: набор заменяется целиком, и опознавать строку по
отдельности незачем (`pricing-settings.md`, правило 14).

## Output

`None`.

## Business Rules

1. Границы формы — иначе `VALIDATION_ERROR` (422): площадь и сумма
   неотрицательные и не выше входных потолков, стороны от нуля до
   `MAX_SIDE_MM`, ступеней не больше `MAX_SIZE_SURCHARGES`.
2. Параметры на сайте заведены — иначе `PRICING_SETTINGS_NOT_FOUND` (404).
   Строка рождается вместе с сайтом, и этот отказ означает незаконченную
   установку, а не ошибку владельца.
3. Коэффициент каждой ступени строго больше единицы — иначе
   `INVALID_SURCHARGE_FACTOR` (400). Наценка выключается пустым набором, и
   второго способа домен не заводит (ADR-0010).
4. Две ступени не начинаются с одной границы — иначе
   `DUPLICATE_SIZE_SURCHARGE` (400): иначе выбор действующей ступени
   неоднозначен.
5. Отказ на наборе ступеней приходит **до** того, как сдвинута хоть одна
   граница: команда одна, и наполовину применённых параметров не бывает.
6. Границы заменяются, набор ступеней заменяется целиком, `updated_at`
   двигается последней строкой, одна транзакция одного агрегата коммитится.
   Публикацию `PricingSettingsChanged` строго после коммита приносит тикет 05
   вместе с инфраструктурой событий и пересчётом (ADR-0014).

## Errors

| Код | HTTP | Когда |
|---|---|---|
| `VALIDATION_ERROR` | 422 | Форма не прошла границы ввода |
| `PRICING_SETTINGS_NOT_FOUND` | 404 | Строки параметров на сайте нет |
| `INVALID_SURCHARGE_FACTOR` | 400 | Коэффициент ступени не больше единицы |
| `DUPLICATE_SIZE_SURCHARGE` | 400 | Две ступени начинаются с одной границы |
