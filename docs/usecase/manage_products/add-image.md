# Заливка фотографии товара

**Актор:** владелец, установленный Django-презентацией.

Владелец выбирает файл на карточке товара; фотография ложится в хранилище, а
товар запоминает выданный ключ. Ни домен, ни приложение не знают ни про диск,
ни про nginx — только про порт `ProductImageStorage` (тикет 08).

## Input

`AddImageForm`

| Поле | Тип | Смысл |
|---|---|---|
| `filename` | `str` | Имя файла, каким его дал браузер: из него берётся расширение |
| `content` | `bytes` | Содержимое файла |

## Output

`CreatedProductImage`

| Поле | Тип | Смысл |
|---|---|---|
| `key` | `str` | Ключ, которым хранилище назвало фотографию |

## Business Rules

1. Имя файла непустое и не длиннее `MAX_NAME_LENGTH`, расширение — одно из
   `IMAGE_EXTENSIONS`, содержимое непустое и не тяжелее `MAX_IMAGE_BYTES` —
   иначе `VALIDATION_ERROR` (422). Форма судит о файле по имени; внутрь
   заглядывает хранилище, когда делает копии.
2. Товар существует — иначе `PRODUCT_NOT_FOUND` (404). Товар берётся под
   замок: галерея правится поштучно, и две заливки в одну карточку — гонка.
3. Ключ придумывает хранилище, а не приложение: в базе лежит строка, которую
   вернул порт, и никогда не путь адаптера. Смена адаптера миграции не стоит.
4. Ключ, который хранилище выдало второй раз, — дефект хранилища, а не отказ
   владельцу: файл живой фотографии уже переписан, и забирать его нельзя.
   Команда падает `RuntimeError` (500) и ничего не удаляет.
5. Товар принимает фотографию командой `add_image` — она встаёт в конец
   галереи. `updated_at` двигается последней строкой, и коммитится одна
   транзакция одного агрегата. Порядок фотографий — поле владельца, но
   команды, которая его переставляет, у агрегата пока нет.
6. Отказ базы после того, как файл лёг в хранилище, забирает файл обратно:
   строки, которая его называет, нет, и ключа не знает больше никто.
7. Рядом с оригиналом хранилище кладёт копии поуже — по одной на каждую
   ширину, которой пользуется витрина. Оригинал остаётся исходником для
   перегенерации. Файл, который не читается как фотография, —
   `IMAGE_NOT_PROCESSABLE` (400), и на томе не остаётся ни оригинала, ни
   копий: карточка после «Сохранить» готова целиком или не меняется вовсе.
   Владелец этот отказ читает на форме — админка отказывает там же, где
   отказывает по весу файла.
8. Соглашение об именах копий живёт внутри адаптера: в базе по-прежнему одна
   непрозрачная строка, и читающая сторона спрашивает у порта, какие копии
   есть, а не выводит их имена сама.

## Errors

| Код | HTTP | Когда |
|---|---|---|
| `VALIDATION_ERROR` | 422 | Форма не прошла границы ввода |
| `PRODUCT_NOT_FOUND` | 404 | Товара нет |
| `IMAGE_NOT_PROCESSABLE` | 400 | Файл не читается как фотография |

`DUPLICATE_PRODUCT_IMAGE` — инвариант агрегата (`docs/entities/product.md`,
правило 17), а не ответ этого сценария: ключи выдаёт хранилище, и повтор
ключа команда объявляет дефектом ещё до `add_image`.
