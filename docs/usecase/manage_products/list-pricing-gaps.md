# Чего товару не хватает до расчёта

**Актор:** владелец, установленный Django-презентацией.

Владелец ведёт зеркала по одному, и список товаров говорит вслух, почему у
товара нет калькулятора: какие атрибуты раздела он ещё не заполнил и не сложен
ли товар из одних бесплатных значений (`docs/entities/product.md`, правило 10).
Сценарий только читает: ни одна команда агрегата отсюда не уходит.

## Input

| Поле | Тип | Смысл |
|---|---|---|
| `product_ids` | `Sequence[UUID]` | Товары одной страницы списка |

## Output

`dict[ProductId, PricingGapsModel]` — по записи на найденный товар. Не
страница коллекции, а ответ про названные товары, поэтому и не конверт
`{items, total, page}`: страницу нарезал спрашивающий.

`PricingGapsModel`

| Поле | Тип | Смысл |
|---|---|---|
| `undeclared_attributes` | `list[str]` | Названия применимых атрибутов раздела, которые товар не заполнил |
| `nothing_is_paid` | `bool` | Всё заполнено, но ни одно значение не стоит денег |

## Business Rules

1. Чего не хватает, решает доменный сервис `pricing_gaps` — тот же, чьим
   ответом витрина закрывает калькулятор: второй формулы «дорос до расчёта» в
   репозитории нет (`AGENTS.md`, «Architecture facts»).
2. Применимость атрибута считается по разделу товара и по его зависимостям:
   атрибут, чей родитель отсутствует, товару не нужен.
3. Пока не заполнено хоть что-то, «ни одно значение не стоит денег» не
   говорится: незаполненный атрибут может оказаться как раз платным.
4. Идентификатор, которого нет, записи не даёт: ответ короче запроса — не
   отказ, товар мог уехать из другого окна.
5. Русские слова колонки — дело админки, отсюда уходят названия атрибутов.
6. Читателей у ответа два: колонка списка товаров и предупреждение над
   сохранённой карточкой — владелец правит товар на карточке и о поломке
   расчёта должен узнать там же, а не в списке.

## Errors

Отказов нет: сценарий читает.
