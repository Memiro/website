# Витрина — Astro SSR с островами Vue; триггер пересмотра — личный кабинет

Витрина отделяется от бэкенда: Astro в SSR-режиме (не SSG — цены и каталог
живут в базе и меняются админкой), интерактив — островами Vue с
`client:visible`. Островов два: калькулятор и форма заявки. Глобального стора
(Pinia) нет — состояние калькулятора живёт в его компоненте. Авторизации на
витрине нет.

Каталог и карточки рендерятся сервером — HTML индексируется без JS-рендера,
чем и был мотивирован отвергаемый ADR-0001; это свойство переезжает вместе с
SEO целиком: sitemap, robots, meta/OG, canonical, JSON-LD и 301-редиректы
легаси-адресов — забота фронта, бэкенд отдаёт данные. SEO переживает будущую
смену стека при сохранении URL: адреса — контракт, рендер — деталь.

У `frontend/` будет свой `AGENTS.md`; правила agent-coding-instruction на
TypeScript не распространяются.

**Триггер пересмотра — личный кабинет.** Пока сайт — витрина с
калькулятором, SSR-остров покрывает весь интерактив. Появление личного
кабинета (авторизация, состояние пользователя между страницами) означает
отдельное SPA под своим путём, не расползание островов; до этого архитектура
фронта не пересматривается.

Отвергнуто: SSG — цены протухали бы до пересборки; SPA сейчас — стоимость и
риски SEO без пользы для витрины на 100–300 товаров (аргумент ADR-0001
против SPA остаётся в силе, меняется только рендерящая сторона).
