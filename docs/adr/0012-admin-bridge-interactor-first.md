# Мост админки: сначала интерактор, затем best-effort Django, один loop-поток

**Решение принято, мост не построен:** `presentation/django_admin/` в `src/`
сегодня нет — его приносит тикет 17 эпика rewrite. Всё ниже описывает, каким
мост будет, а не то, что уже работает.

Django-админка остаётся рабочим местом владельца, но перестаёт быть хозяйкой
домена: она — вторая презентация того же bounded context
(`presentation/django_admin/` рядом с `presentation/fast_api/`), не отдельный
пакет и не отдельный контекст. Читает она напрямую по зеркалам доменных таблиц
(`managed = False`, явный `db_table`, во всех зеркалах
`on_delete=DO_NOTHING` — правила удаления принадлежат БД и домену). Пишет —
через те же интеракторы, что и API, импортом, не по HTTP.

**Порядок записи фиксирован: сначала интерактор, затем Django-часть
best-effort.** Форма админки собирает команду и зовёт корневой интерактор —
он и коммитит домен одной транзакцией. Только после этого выполняется
Django-часть: запись в историю (`LogEntry`), messages-баннеры. Её падение —
warning в лог, домен не откатывается: история админки — удобство оператора,
а не инвариант. Обратный порядок означал бы либо историю о несостоявшейся
записи, либо распределённую транзакцию между доменом и служебными таблицами
Django — ни того ни другого здесь не нужно.

Бизнес-отказ интерактора (`AppError`) — сообщение об ошибке и возврат на
форму; не сохранено ничего, потому что доменная транзакция одна и она не
прошла. Ошибки формата ловит сама форма до интерактора.

**Мост async — постоянный фоновый поток с одним event loop на процесс
админки.** Админка — WSGI и синхронна, интеракторы — async. `bridge.py`
держит поток с живым loop'ом и отправляет корутины через
`run_coroutine_threadsafe`; dishka-контейнер и engine создаются в этом loop'е
один раз — честный APP-scope, поведение идентично API-процессу, на каждый
запрос открывается только REQUEST-scope.

Отвергнуто: вызовы API по HTTP из админки (вторая аутентификация, сериализация
и сетевая ошибка там, где достаточно импорта — контексту разрешено иметь две
презентации); loop на каждый вызов (`asyncio.run`/`async_to_sync` с новым
loop'ом) — engine и пул соединений живут в loop'е, пересоздавать их на каждую
запись значит не иметь APP-scope вовсе.
